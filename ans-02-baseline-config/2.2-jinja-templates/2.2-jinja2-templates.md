# 2.2 Jinja2 templates

**Task:** generate interface configs from `host_vars`.

## What you'll learn

| Concept | In one line |
|---|---|
| `host_vars/` | A folder of per-device variables that Ansible loads automatically |
| Jinja2 template | A config file with gaps that get filled in from variables |
| `ansible.builtin.template` | Renders a template into a real file |
| `delegate_to: localhost` | Runs a task on your computer instead of the device |

This lesson **doesn't touch the routers.** It only builds config files on your
computer. Lesson 2.3 pushes them.

## Files

```
ansible-lab/
├── hosts.yml
├── interfaces.yml        <- NEW  playbook
├── host_vars/            <- NEW
│   ├── R1.yml            <- NEW  R1's interface data
│   └── R2.yml            <- NEW  R2's interface data
├── templates/            <- NEW
│   └── interfaces.j2     <- NEW  the template
└── configs/                       created by the playbook
    ├── R1.cfg
    └── R2.cfg
```

## How it works

```
host_vars/R1.yml  ─┐
(the data)         ├──>  template module  ──>  configs/R1.cfg
templates/         │                           (finished IOS config)
interfaces.j2  ────┘
(the layout)
```

## The files explained

### `host_vars/R1.yml`: R1's data

```yaml
interfaces:
  - name: Loopback0
    ip: 10.255.0.1
    mask: 255.255.255.0

  - name: Loopback99
    ip: 10.0.0.250
    mask: 255.255.255.255

  - name: GigabitEthernet1
    shutdown: true

  - name: GigabitEthernet2
    description: to R2
    ip: 10.0.12.1
    mask: 255.255.255.252

  - name: GigabitEthernet3
    description: to R4
    ip: 10.0.41.2
    mask: 255.255.255.252

  - name: GigabitEthernet4
    description: to R3 (cross)
    ip: 10.0.13.1
    mask: 255.255.255.252
```

- Ansible loads this file for **R1** automatically, because the file name matches the host name in `hosts.yml`. Names are case-sensitive: `r1.yml` won't load.
- Only put the **differences** here: names, IPs, descriptions. Anything every interface has goes in the template.
- Keys are optional. GigabitEthernet1 has no `ip`, and Loopback99 has no `description`. The template handles both.

### `host_vars/R2.yml`: R2's data

```yaml
interfaces:
  - name: Loopback0
    ip: 10.255.0.2
    mask: 255.255.255.0

  - name: GigabitEthernet1
    shutdown: true

  - name: GigabitEthernet2
    description: to R1
    ip: 10.0.12.2
    mask: 255.255.255.252

  - name: GigabitEthernet3
    description: to R3
    ip: 10.0.23.1
    mask: 255.255.255.252
```

Same shape, different values. That's the point: **one template, many devices.**

### `templates/interfaces.j2`: the template

```jinja
{% for intf in interfaces %}
interface {{ intf.name }}
{% if intf.description is defined %}
 description {{ intf.description }}
{% endif %}
{% if intf.ip is defined %}
 ip address {{ intf.ip }} {{ intf.mask }}
{% else %}
 no ip address
{% endif %}
{% if intf.shutdown | default(false) %}
 shutdown
{% endif %}
{% if intf.name.startswith('GigabitEthernet') %}
 negotiation auto
 cdp enable
 no mop enabled
 no mop sysid
{% endif %}
!
{% endfor %}
```

Jinja2 has three kinds of tags:

| Syntax | Meaning | Example |
|---|---|---|
| `{{ ... }}` | Print a value | `{{ intf.name }}` → `GigabitEthernet2` |
| `{% for %} ... {% endfor %}` | Repeat for each item | One block per interface |
| `{% if %} ... {% else %} ... {% endif %}` | Include only if true | Description line only if one exists |

What each `if` does:

| Block | Why |
|---|---|
| `intf.description is defined` | Loopbacks and Gi1 have no description, so the line is skipped |
| `intf.ip is defined` / `else` | Interfaces without an IP get `no ip address` |
| `intf.shutdown \| default(false)` | `default(false)` means "if `shutdown` isn't set, treat it as false" |
| `intf.name.startswith('GigabitEthernet')` | Physical-only lines (negotiation, CDP, MOP). Loopbacks skip them |

### `interfaces.yml`: the playbook

```yaml
---
- name: Generate interface configs from host_vars
  hosts: core_hosts
  gather_facts: false

  tasks:
    - name: Make the configs folder
      ansible.builtin.file:
        path: configs
        state: directory
        mode: "0755"
      delegate_to: localhost
      run_once: true

    - name: Build config from template
      ansible.builtin.template:
        src: templates/interfaces.j2
        dest: "configs/{{ inventory_hostname }}.cfg"
        mode: "0644"
      delegate_to: localhost
```

| Line | What it does |
|---|---|
| `ansible.builtin.file` + `state: directory` | Makes the `configs/` folder |
| `run_once: true` | Only make the folder once, not once per router |
| `ansible.builtin.template` | Fills the template with this host's variables |
| `dest: "configs/{{ inventory_hostname }}.cfg"` | `inventory_hostname` is the device name, so you get `R1.cfg` and `R2.cfg` |
| `delegate_to: localhost` | Write the file on **your computer**, not on the router |
| `mode:` | File permissions. ansible-lint (lesson 4.2) wants these set |

## Run it

```bash
ansible-playbook interfaces.yml
```

No `-k` is needed, because nothing connects to the routers.

## Try this

1. Run the playbook twice. The second run shows `changed=0`, because the files already match.
2. Add a `GigabitEthernet5` to `R2.yml` and run again. Only `R2.cfg` changes.
3. Add `mtu: 1400` to one interface, and add this to the template under the IP block:
   ```jinja
   {% if intf.mtu is defined %}
    mtu {{ intf.mtu }}
   {% endif %}
   ```
4. Create `host_vars/R3.yml` and change `hosts:` to `routers`. What happens to R4, which has no host_vars? (Hint: add `when: interfaces is defined` to the template task.)

## Common mistakes

| Mistake | Fix |
|---|---|
| `'interfaces' is undefined` | host_vars file name doesn't match the host, `host_vars/` is in the wrong folder, or the key is misspelled. Check with `ansible-inventory --host R1` |
| Blank lines everywhere in the output | Ansible trims these by default. If you see them, check you didn't add spaces after `%}` |
| `Could not find or access 'templates/interfaces.j2'` | `templates/` must sit next to the playbook |
| Indentation wrong in output | The space before `description`, `ip address`, etc. in the template **is** the IOS indent. Keep it |
