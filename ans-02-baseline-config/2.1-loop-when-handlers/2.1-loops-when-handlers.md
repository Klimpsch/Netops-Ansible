# 2.1 Loops, when and handlers

**Task:** write a playbook that pushes NTP only to the core group.

## What you'll learn

| Concept | In one line |
|---|---|
| `hosts:` | Picks which devices a play runs on |
| `loop` | Runs the same task once for each item in a list |
| `when` | Runs a task only if a condition is true |
| `handlers` | Tasks that run only when something changed |
| `vars_files` | Loads variables from a separate file |

## Files

```
ansible-lab/
├── ansible.cfg
├── hosts.yml
├── vars.yml        <- NEW  the NTP server list
└── ntp-core.yml    <- NEW  the playbook
```

## The files explained

### `vars.yml`: the data

```yaml
ntp_servers:
  - 10.0.0.250
  - 10.0.0.251
```

This is just a list. To add or remove an NTP server you only edit this file, never
the playbook. Keeping **data** separate from **logic** is a habit you'll use in
every lesson.

### `ntp-core.yml`: the playbook

```yaml
---
- name: Push NTP to core routers
  hosts: core_hosts
  gather_facts: false
  vars_files:
    - vars.yml

  tasks:
    - name: Add NTP servers
      cisco.ios.ios_config:
        lines:
          - "ntp server {{ item }}"
      loop: "{{ ntp_servers }}"
      when: ansible_network_os == "cisco.ios.ios"
      notify: Save config

  handlers:
    - name: Save config
      cisco.ios.ios_command:
        commands: write memory
```

Line by line:

| Line | What it does |
|---|---|
| `hosts: core_hosts` | Only R1 and R2 are targeted. R3 and R4 are never touched |
| `gather_facts: false` | Skips fact gathering. Network devices don't need it here, and it's faster |
| `vars_files: - vars.yml` | Loads `ntp_servers` from `vars.yml` |
| `cisco.ios.ios_config` | Sends config lines to the device. Only sends lines that are missing |
| `loop: "{{ ntp_servers }}"` | **LOOP:** runs the task once per server |
| `"ntp server {{ item }}"` | `item` is the current server from the list |
| `when: ...` | **WHEN:** only runs if the device is Cisco IOS |
| `notify: Save config` | **HANDLER:** if this task changed anything, run "Save config" at the end |
| `handlers:` | The "Save config" handler runs `write memory` |

## How handlers behave

```
Task "Add NTP servers"
  item 10.0.0.250 -> changed  --notify-->  ┐
  item 10.0.0.251 -> changed  --notify-->  ├─> "Save config" runs ONCE, at the end of the play
                                           ┘
Nothing changed?  ->  handler never runs  ->  no needless write memory
```

## Run it

```bash
ansible-playbook ntp-core.yml --syntax-check   # check for typos first
ansible-playbook ntp-core.yml -k               # -k asks for the SSH password
```

## What you should see

**First run**, when NTP isn't configured yet:

- `Add NTP servers` shows `changed` for each server.
- `RUNNING HANDLER [Save config]` appears.

**Second run:**

- Each server shows `ok`, not `changed`, because the lines already exist.
- The handler does **not** run.

Check on R1:

```
R1# show running-config | include ntp
```

## Try this

1. Add a third server to `vars.yml` and run again. Only the new one shows `changed`.
2. Change `hosts: core_hosts` to `hosts: routers`. Now R3 and R4 get it too.
3. Change the `when` to `when: inventory_hostname != "R1"`. R1 is skipped. (Useful because R1 *is* 10.0.0.250, so it shouldn't point NTP at itself. Lesson 2.4 uses this.)
4. Add `loop_control:` with `label: "{{ item }}"` under the loop. What changes in the output?

## Common mistakes

| Mistake | Fix |
|---|---|
| `'ntp_servers' is undefined` | `vars.yml` isn't next to the playbook, or the key is misspelled |
| `item` is undefined | `loop:` must be at the same indent level as the module name |
| Handler never runs | Handler `name:` must match `notify:` exactly, including capitals |
| Playbook hits R3/R4 | Check `hosts:`. It should be `core_hosts` |
