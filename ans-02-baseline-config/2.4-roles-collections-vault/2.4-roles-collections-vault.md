# 2.4 Roles, collections and Vault

**Task:** combine everything into a `baseline` role covering NTP, banner, logging and
SNMP, with the credentials stored in Vault.

## What you'll learn

| Concept | In one line |
|---|---|
| Role | A reusable package of tasks, defaults and handlers in a fixed folder layout |
| `defaults/main.yml` | A role's default variable values, easy to override |
| `include_tasks` | Splits a role into smaller task files |
| Collection | A package of modules (like `cisco.ios`) you install with `ansible-galaxy` |
| `requirements.yml` | Lists the collections your project needs |
| Ansible Vault | Encrypts secrets so they can live safely in Git |
| `no_log: true` | Hides a task's output so secrets don't show in logs |

## Files

```
ansible-lab/
├── ansible.cfg                   <- CHANGED  adds the Vault password file (Step 5)
├── baseline.yml                  <- NEW  short playbook that calls the role
├── .gitignore                    <- NEW
├── .vault_pass                   <- NEW  Vault password (NEVER commit)
├── collections/
│   └── requirements.yml          <- NEW
├── group_vars/
│   └── all/
│       ├── vars.yml              <- NEW  plain text, points to the secrets
│       └── vault.yml             <- NEW  encrypted secrets
└── roles/
    └── baseline/                 <- NEW
        ├── defaults/main.yml         default values
        ├── handlers/main.yml         "Save config"
        ├── meta/main.yml             info about the role
        └── tasks/
            ├── main.yml              calls the four files below
            ├── ntp.yml
            ├── banner.yml
            ├── logging.yml
            └── snmp.yml
```

## Part A: Collections

Modules like `cisco.ios.ios_config` come from **collections**. The full `ansible`
package includes them, but a real project should say exactly what it needs.

### `collections/requirements.yml`

```yaml
---
collections:
  - name: cisco.ios
  - name: ansible.netcommon
```

```bash
ansible-galaxy collection install -r collections/requirements.yml
```

Because `ansible.cfg` sets `collections_path = collections`, they install into
this project. Anyone who clones your repo runs the same command and gets the same modules.

## Part B: Vault

### Step 1: Create a password file

```bash
echo 'pick-a-strong-password' > .vault_pass
chmod 600 .vault_pass
```

### Step 2: Keep it out of Git

`.gitignore`:

```text
.vault_pass
configs/
collections/ansible_collections/
```

**Never commit `.vault_pass`.** Anyone with it can decrypt your secrets.

### Step 3: Create the encrypted secrets file

```bash
mkdir -p group_vars/all
ansible-vault create group_vars/all/vault.yml --vault-password-file .vault_pass
```

An editor opens. Type:

```yaml
---
vault_ansible_password: Cisco123
vault_snmp_community: S3cretRO
```

Save and close. The file on disk now looks like this:

```
$ANSIBLE_VAULT;1.1;AES256
64323039366134633234623938353130373436316632353830...
```

Useful commands:

```bash
ansible-vault view group_vars/all/vault.yml --vault-password-file .vault_pass
ansible-vault edit group_vars/all/vault.yml --vault-password-file .vault_pass
# after Step 5 you can drop --vault-password-file from these too
```

### Step 4: Point to the secrets from a plain file

`group_vars/all/vars.yml`:

```yaml
---
# Plain-text pointers to the secret values in vault.yml.
# Anyone can read this file and see WHICH secrets exist, but not their values.
ansible_password: "{{ vault_ansible_password }}"
baseline_snmp_community: "{{ vault_snmp_community }}"
```

**Why two files?** You can `grep` for `snmp_community` and find *where* it's set,
without decrypting anything. The `vault_` prefix makes it obvious the real value is
encrypted. This is the standard pattern.

`group_vars/all/` applies to every host. Ansible loads every file in that folder.

Because `ansible_password` now comes from Vault, you no longer need `-k`.

### Step 5: Tell Ansible where the password file is

Add this line to `ansible.cfg` under `[defaults]`:

```ini
vault_password_file = .vault_pass
```

**This step matters.** `group_vars/all/` applies to every host, so from now on
*every* playbook (even `interfaces.yml` from 2.2) needs to decrypt the Vault. Without
this line you'd get `Attempting to decrypt but no vault secrets found` on everything.

## Part C: The role

### `roles/baseline/defaults/main.yml`: the settings

```yaml
---
# Default values for the baseline role.
# Override any of these in group_vars or host_vars.

baseline_ntp_servers:
  - 10.0.0.250
  - 10.0.0.251

# R1 owns 10.0.0.250 (Loopback99), so it shouldn't point NTP at itself
baseline_ntp_master: R1

baseline_banner: |
  Authorised access only.
  Disconnect now if you are not an authorised user.

baseline_logging_host: 10.0.0.50
baseline_logging_buffer: 16384

baseline_snmp_location: Lab
baseline_snmp_contact: netops@example.com
# The community string itself comes from Vault (see group_vars/all/vars.yml)
```

- Defaults have the **lowest priority**. Anything in `group_vars` or `host_vars` overrides them.
- Every variable starts with `baseline_`. That shows which role owns it, and ansible-lint (lesson 4.2) checks for it.
- `baseline_ntp_master: R1` is there because R1 *is* the NTP server.

### `roles/baseline/tasks/main.yml`: the entry point

```yaml
---
- name: NTP
  ansible.builtin.include_tasks: ntp.yml

- name: Banner
  ansible.builtin.include_tasks: banner.yml

- name: Logging
  ansible.builtin.include_tasks: logging.yml

- name: SNMP
  ansible.builtin.include_tasks: snmp.yml
```

When a role runs, Ansible starts at `tasks/main.yml`. This one just calls four
smaller files, so each feature is easy to find.

### `roles/baseline/tasks/ntp.yml`

```yaml
---
- name: Add NTP servers
  cisco.ios.ios_config:
    lines:
      - "ntp server {{ item }}"
  loop: "{{ baseline_ntp_servers }}"
  when: inventory_hostname != baseline_ntp_master
  notify: Save config
```

Lesson 2.1's loop, now using role variables. The `when` skips R1.

### `roles/baseline/tasks/banner.yml`

```yaml
---
- name: Set login banner
  cisco.ios.ios_banner:
    banner: motd
    text: "{{ baseline_banner }}"
    state: present
  notify: Save config
```

`ios_banner` is a dedicated module. It handles the awkward `^C` delimiters for you.

### `roles/baseline/tasks/logging.yml`

```yaml
---
- name: Configure logging
  cisco.ios.ios_config:
    lines:
      - "logging buffered {{ baseline_logging_buffer }}"
      - "logging host {{ baseline_logging_host }}"
  notify: Save config
```

### `roles/baseline/tasks/snmp.yml`

```yaml
---
- name: Configure SNMP
  cisco.ios.ios_config:
    lines:
      - "snmp-server community {{ baseline_snmp_community }} RO"
      - "snmp-server location {{ baseline_snmp_location }}"
      - "snmp-server contact {{ baseline_snmp_contact }}"
  no_log: true          # keeps the community string out of the output
  notify: Save config
```

`no_log: true` stops Ansible printing the task's details, so the community string
never appears on screen or in CI logs.

### `roles/baseline/handlers/main.yml`

```yaml
---
- name: Save config
  cisco.ios.ios_config:
    save_when: modified
```

All four task files notify this one handler. It runs **once** at the end, however
many tasks changed something.

### `roles/baseline/meta/main.yml`

```yaml
---
galaxy_info:
  author: you
  description: Baseline config for Cisco IOS routers (NTP, banner, logging, SNMP)
  license: MIT
  min_ansible_version: "2.15"
  platforms:
    - name: IOS
      versions:
        - all
dependencies: []
```

A description of the role. It's required if you ever share it on Ansible Galaxy,
and ansible-lint expects it.

### `baseline.yml`: the playbook

```yaml
---
- name: Apply baseline config to all routers
  hosts: routers
  gather_facts: false

  roles:
    - baseline
```

Compare this with lesson 2.1. All the logic now lives in the role, so the playbook
is just "which hosts, which role".

## Run it

```bash
ansible-playbook baseline.yml --syntax-check
ansible-playbook baseline.yml --check --diff
ansible-playbook baseline.yml
ansible-playbook baseline.yml    # expect changed=0
```

No `-k` and no `--vault-password-file` are needed, thanks to Step 5.

## What you should see

- R1: the NTP task shows `skipping`, and banner, logging and SNMP apply.
- R2–R4: all four apply.
- The SNMP task shows `censored` in place of its details.
- The handler runs once per router.
- Second run: `changed=0` everywhere.

## Try this

1. Override a default for one router only: create `host_vars/R3.yml` with `baseline_snmp_location: Edge-Site-B`.
2. Use tags so you can run one feature at a time. In `tasks/main.yml`, change the NTP entry to:
   ```yaml
   - name: NTP
     ansible.builtin.include_tasks:
       file: ntp.yml
       apply:
         tags: ntp
     tags: ntp
   ```
   Then run `ansible-playbook baseline.yml --tags ntp`.
3. Change the Vault password: `ansible-vault rekey group_vars/all/vault.yml`.
4. Delete `ntp-core.yml` from 2.1. The role replaces it.

## Common mistakes

| Mistake | Fix |
|---|---|
| `Attempting to decrypt but no vault secrets found` | Step 5 is missing, or `.vault_pass` isn't in the project folder |
| `the role 'baseline' was not found` | Check `roles_path = roles` in `ansible.cfg` and the folder name |
| Role variable ignored | Defaults are lowest priority, so something in `group_vars` or `host_vars` is overriding it |
| `.vault_pass` committed to Git | Change the Vault password (`rekey`) **and** every secret in it. Removing the file isn't enough, because it's still in Git history |
