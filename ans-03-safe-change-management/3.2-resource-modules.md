# 3.2 Resource modules: ios_vlans, ios_interfaces, ios_ospfv2

**Task:** manage VLANs from YAML using `state: overridden`.

## What you'll learn

| Concept | In one line |
|---|---|
| Resource module | You describe the **end state** as data. The module works out the commands |
| `state: gathered` | Read the device's current config **as YAML**. Changes nothing |
| `state: merged` | Add or update what you list. Never removes anything |
| `state: replaced` | Make the listed items match exactly. Leave unlisted items alone |
| `state: overridden` | Make the **whole device** match your list. Removes anything not listed |
| `state: deleted` | Remove what you list |

## ios_config vs resource modules

| | `ios_config` (3.1) | Resource modules (this lesson) |
|---|---|---|
| You write | CLI lines | YAML data |
| Removing things | You write the `no ...` lines | `overridden` / `replaced` / `deleted` do it for you |
| Reading config | Text you have to parse | `gathered` gives you structured data |
| Covers | Anything | One feature per module (VLANs, interfaces, OSPF...) |

VLANs need a **switch**. Routers don't have a VLAN database. In CML or EVE-NG, add
an IOSvL2 switch and call it SW1. `hosts.yml` from the setup already has a
`switches` group with SW1 in it. Steps 1 and 2 work on your routers.

## Step 1: `state: gathered`, read before you write

Always start here. It shows you the data shape each module expects.

### `gather.yml`

```yaml
---
- name: Read current config as structured data
  hosts: core_hosts
  gather_facts: false

  tasks:
    - name: Gather interfaces
      cisco.ios.ios_interfaces:
        state: gathered
      register: intf

    - name: Gather OSPF
      cisco.ios.ios_ospfv2:
        state: gathered
      register: ospf

    - name: Show interfaces
      ansible.builtin.debug:
        var: intf.gathered

    - name: Show OSPF
      ansible.builtin.debug:
        var: ospf.gathered
```

```bash
ansible-playbook gather.yml
```

You'll get output like this (shortened):

```yaml
intf.gathered:
  - name: GigabitEthernet2
    description: to R2
    enabled: true
  - name: GigabitEthernet1
    enabled: false
ospf.gathered:
  processes:
    - process_id: 1
      ...
```

That YAML is **exactly** what you'd feed back in as `config:`. Gather, copy, edit,
apply is the standard workflow.

`ios_ospfv2` is in this lesson to show that OSPF has a data model too. Look at the
gathered output to see how OSPF is described in YAML. Lesson 3.3 makes a real OSPF change.

## Step 2: `state: merged`, the safe one

### `descriptions.yml`

Reuses the `interfaces` data from your `host_vars` (lesson 2.2), so the
descriptions only live in one place.

```yaml
---
- name: Set interface descriptions with a resource module
  hosts: core_hosts
  gather_facts: false

  tasks:
    - name: Build a list in the shape ios_interfaces expects
      ansible.builtin.set_fact:
        intf_config: "{{ intf_config | default([]) + [{'name': item.name, 'description': item.description}] }}"
      loop: "{{ interfaces }}"
      when: item.description is defined

    - name: Show what will be sent
      ansible.builtin.debug:
        var: intf_config

    - name: Apply descriptions (merged = only add/change, never remove)
      cisco.ios.ios_interfaces:
        config: "{{ intf_config }}"
        state: merged
```

| Line | What it does |
|---|---|
| `set_fact` + `loop` | Builds a new list with only `name` and `description` |
| `intf_config \| default([]) + [...]` | Start with an empty list, add one item per loop |
| `when: item.description is defined` | Skip interfaces with no description |
| `state: merged` | Set these descriptions. Leave everything else on the router alone |

```bash
ansible-playbook descriptions.yml --check --diff
ansible-playbook descriptions.yml
```

The descriptions already match, so you should see `changed=0`. Now change one in
`host_vars/R1.yml` and run again.

## Step 3: `state: overridden`, the powerful one

### `group_vars/switches/vlans.yml`: the VLAN list

```yaml
---
vlans:
  - vlan_id: 10
    name: USERS
  - vlan_id: 20
    name: VOICE
  - vlan_id: 99
    name: MGMT
```

This file applies to every host in the `switches` group. This list is now the
**only truth** for VLANs on those switches.

### `vlans.yml`: the playbook

```yaml
---
- name: Manage VLANs from YAML
  hosts: switches
  gather_facts: false

  tasks:
    - name: Make the switch VLANs match vlans.yml exactly
      cisco.ios.ios_vlans:
        config: "{{ vlans }}"
        state: overridden
```

What `overridden` does:

```
On SW1 now:     10 USERS   20 VOICE   30 OLD-PRINTERS   99 MGMT
In vlans.yml:   10 USERS   20 VOICE                     99 MGMT
                                      ──────────────
                                      not in the file → DELETED
```

### Run it carefully

```bash
# 1. See what's there now
#    (copy gather.yml, point it at switches, and use cisco.ios.ios_vlans)

# 2. Dry run. READ the output. Anything being removed?
ansible-playbook vlans.yml --check --diff -v

# 3. Apply
ansible-playbook vlans.yml

# 4. Idempotency check: expect changed=0
ansible-playbook vlans.yml
```

### Prove it works

1. On SW1, add a VLAN by hand: `vlan 30` / `name OLD-PRINTERS`.
2. Run `vlans.yml` again.
3. VLAN 30 is gone. The YAML file won.

This is how you stop "config drift": nobody can quietly add something that
survives the next run.

## Which state should I use?

| Situation | Use |
|---|---|
| Just looking | `gathered` |
| Adding something, don't touch anything else | `merged` |
| These specific items must look exactly like this | `replaced` |
| The whole device must match my file, nothing extra | `overridden` |
| Remove these items | `deleted` |

**Be careful with `overridden` on `ios_interfaces`.** Every interface not in your
list gets reset to defaults, including its description and shutdown state.
Use `merged` or `replaced` for interfaces until you're confident.

## Try this

1. Add VLAN 40 to the YAML and run. Then remove it from the YAML and run. It's deleted from the switch.
2. Change `overridden` to `merged` and repeat step 1. What's different?
3. Write `gather-vlans.yml`: `ios_vlans` with `state: gathered` against `switches`. Compare its output with your YAML.
4. Try `state: rendered` with `config:`. It shows the CLI commands the module would generate.

## Common mistakes

| Mistake | Fix |
|---|---|
| VLAN 1 or 1002–1005 errors | Those are built-in VLANs. If the module complains, run `gathered` and copy how they appear into your list |
| Something vanished you wanted | That's `overridden`. Always `--check --diff` first |
| `Unsupported parameters` | Your YAML keys don't match the module. Run `gathered` and copy its shape |
| VLAN playbook hits routers | Check `hosts: switches` |
