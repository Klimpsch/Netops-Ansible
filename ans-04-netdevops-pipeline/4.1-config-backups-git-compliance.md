# 4.1 Config backups to Git, and a compliance check

**Task:** back up every router's config into Git, then write a compliance playbook that
lists devices missing NTP or a banner, checked against those backups.

## What you'll learn

| Concept | In one line |
|---|---|
| Fixed backup filenames | Same file each time, so Git tracks the changes |
| `command` + `changed_when` / `failed_when` | Run a shell command and decide yourself what "changed" or "failed" means |
| `lookup('file', ...)` | Reads a file on your computer into a variable |
| `is search(...)` | True if some text contains a pattern |
| `hostvars` + `map` / `rejectattr` | Combine results from every host into one report |

## Files

```
ansible-lab/
├── backup.yml            <- NEW  back up + git commit
├── compliance.yml        <- NEW  read backups, report problems
└── backups/              created by backup.yml, tracked in Git
    ├── R1.cfg
    ├── R2.cfg
    ├── R3.cfg
    └── R4.cfg
```

## Why Git for backups?

```
backups/R1-2026-11-01.cfg       vs        backups/R1.cfg   + git
backups/R1-2026-11-02.cfg                 git log backups/R1.cfg
backups/R1-2026-11-03.cfg                 git diff HEAD~1 backups/R1.cfg
...hundreds of files                      one file, full history, exact diffs
```

Git answers "what changed on R1 since Tuesday?" in one command.

## Part A: backups

### `backup.yml`

```yaml
---
- name: Back up running configs and commit them to Git
  hosts: routers
  gather_facts: false

  tasks:
    - name: Save running config to backups/<host>.cfg
      cisco.ios.ios_config:
        backup: true
        backup_options:
          dir_path: backups
          filename: "{{ inventory_hostname }}.cfg"

    - name: Stage the backups in Git
      ansible.builtin.command: git add backups  # noqa: command-instead-of-module
      delegate_to: localhost
      run_once: true
      changed_when: false

    - name: Commit (only if a config changed)
      ansible.builtin.command: git commit -m "Config backup {{ now(fmt='%Y-%m-%d %H:%M') }}"  # noqa: command-instead-of-module
      delegate_to: localhost
      run_once: true
      register: commit
      changed_when: commit.rc == 0
      failed_when: commit.rc not in [0, 1]
```

| Line | What it does |
|---|---|
| `backup: true` with no `lines:` | Just take a backup. Nothing is changed |
| `filename: "{{ inventory_hostname }}.cfg"` | **Same name every time.** Git sees it as one file changing |
| `delegate_to: localhost` + `run_once: true` | Run the git command once, on your computer |
| `changed_when: false` | `git add` isn't a "change" worth reporting |
| `commit.rc` | `rc` is the command's exit code. `git commit` returns 0 if it committed and 1 if there was nothing to commit |
| `changed_when: commit.rc == 0` | Report `changed` only when a real commit happened |
| `failed_when: commit.rc not in [0, 1]` | "Nothing to commit" (1) isn't an error. Anything else is |
| `# noqa: command-instead-of-module` | Tells ansible-lint (4.2) "yes, I meant to use `command` here". The `git` module can clone but can't commit |

### Run it

```bash
ansible-playbook backup.yml
git log --oneline backups/
```

Then change something on R2 by hand (a description, say) and run it again:

```bash
ansible-playbook backup.yml
git log --oneline backups/R2.cfg     # a new commit
git diff HEAD~1 -- backups/R2.cfg    # exactly what changed
```

If nothing changed on any router, the backup files are identical, Git has nothing
to commit, and the commit task shows `ok`. Run it twice in a row to see this.

The `! Last configuration change at ...` line near the top of each backup updates
whenever someone touches the config, even if they changed it back. A commit with
only that line in the diff means "someone was in config mode".

## Part B: compliance

The compliance check reads the **backup files**, not the live routers. It's fast,
works when a router is down, and checks exactly what's in Git.

### `compliance.yml`

```yaml
---
- name: Check backed-up configs for NTP and a banner
  hosts: routers
  gather_facts: false

  tasks:
    - name: Read this router's backup file
      ansible.builtin.set_fact:
        running: "{{ lookup('ansible.builtin.file', 'backups/' ~ inventory_hostname ~ '.cfg', errors='ignore') | default('', true) }}"

    - name: Check each rule
      ansible.builtin.set_fact:
        has_backup: "{{ running | length > 0 }}"
        has_ntp: "{{ running is search('^ntp server', multiline=True) }}"
        has_banner: "{{ running is search('^banner motd', multiline=True) }}"

    - name: Compliance report
      ansible.builtin.debug:
        msg:
          - "No backup file: {{ ansible_play_hosts | map('extract', hostvars) | rejectattr('has_backup') | map(attribute='inventory_hostname') | list }}"
          - "Missing NTP:    {{ ansible_play_hosts | map('extract', hostvars) | rejectattr('has_ntp') | map(attribute='inventory_hostname') | list }}"
          - "Missing banner: {{ ansible_play_hosts | map('extract', hostvars) | rejectattr('has_banner') | map(attribute='inventory_hostname') | list }}"
      run_once: true
```

**Task 1: read the backup**

`lookup('ansible.builtin.file', 'backups/R1.cfg')` reads the file from your
computer. Lookups always run locally, so no connection to the router is needed.
`errors='ignore'` plus `default('', true)` means a missing file gives empty text
rather than crashing.

**Task 2: check each rule**

| Variable | True when |
|---|---|
| `has_backup` | The file had any content |
| `has_ntp` | A line **starts with** `ntp server` |
| `has_banner` | A line **starts with** `banner motd` |

`multiline=True` makes `^` mean "start of any line", not just the start of the file.

**Task 3: the report**

Read this one from the inside out:

```
ansible_play_hosts                        ['R1', 'R2', 'R3', 'R4']
| map('extract', hostvars)                each host's variables
| rejectattr('has_ntp')                   drop the ones where has_ntp is true
| map(attribute='inventory_hostname')     keep just the names
| list                                    ['R3', 'R4']
```

`run_once: true` prints one report, not four.

### Run it

```bash
ansible-playbook backup.yml        # fresh backups first
ansible-playbook compliance.yml
```

### What you should see

Example output from a test run (R4 had no backup, R3 had no NTP, R2 had no banner):

```
"msg": [
    "No backup file: ['R4']",
    "Missing NTP:    ['R3', 'R4']",
    "Missing banner: ['R2', 'R4']"
]
```

If you ran the `baseline` role from 2.4, everything should be compliant, except R1
for NTP, because the role skips R1 on purpose. That's a useful finding: your
compliance rules and your config rules must agree. Try this #2 fixes it.

## Try this

1. Add a rule: `has_logging` = `running is search('^logging host', multiline=True)`, and add it to the report.
2. Exclude R1 from the NTP rule, because it's the NTP server: use `has_ntp: "{{ inventory_hostname == 'R1' or running is search(...) }}"`.
3. Make the playbook **fail** if anything is non-compliant, so it can gate a pipeline. Add a final task:
   ```yaml
   - name: Fail if anything is non-compliant
     ansible.builtin.assert:
       that:
         - has_ntp
         - has_banner
       fail_msg: "{{ inventory_hostname }} is not compliant"
   ```
4. Run `backup.yml` on a schedule with `cron` (Linux) so the history builds up by itself.

## Common mistakes

| Mistake | Fix |
|---|---|
| `fatal: not a git repository` | Run `git init` in the project folder first |
| `git commit` fails with "Please tell me who you are" | Run `git config user.name "You"` and `git config user.email "you@example.com"` |
| Every host shows as missing everything | `backups/` is empty or in the wrong place. Run `backup.yml` first |
| `has_ntp` false but NTP is configured | Check the exact line in the backup. Maybe it's `ntp server vrf MGMT ...`. Adjust the pattern |
